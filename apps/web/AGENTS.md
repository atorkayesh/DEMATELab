# DEMATELab Web - Agent Guidelines

TanStack Start app for DEMATELab. For the whole-app workflow (Docker, cross-app changes), see the
[root `AGENTS.md`](../../AGENTS.md). Human-facing setup is in [`apps/web/README.md`](./README.md).
The API contract is in `docs/plans/2026-11-16-port-backend-to-fastapi-api-plan.md` (API Contract) and
the UI plan in `docs/plans/2026-11-16-rebuild-ui-in-tanstack-start-plan.md`.

**Stack:** TanStack Start (React 19, TanStack Router file routes, Vite, Nitro server), TypeScript
(strict), pnpm, Node.js 24, Tailwind CSS v4, Shadcn UI on Base UI, TanStack Query, Zustand, Zod,
Biome, Vitest

---

## Commands

Run these in the dev container from the repo root: `make check-web`, `make test-web T=<filter>`,
`make format`, `make sh-web`. The commands below are what they run, and also work outside Docker.

```bash
cd apps/web

pnpm install
pnpm run dev            # Dev server at http://localhost:3000 (API at http://localhost:50001)
pnpm run build          # Production build → .output/
pnpm run start          # Start the production server (.output/server/index.mjs)

pnpm run format         # Biome format: ALWAYS run before committing
pnpm run format:check   # Biome format check
pnpm run lint           # Biome lint
pnpm run check          # Biome lint + format + import order (errors only)
pnpm run typecheck      # tsc --noEmit

pnpm run test           # Vitest
pnpm run test:watch     # Watch mode
pnpm run test:coverage  # Coverage report

pnpm dlx shadcn@latest add <component>   # Add a Shadcn UI component (never by hand)
```

Only pnpm is used. Commit `pnpm-lock.yaml`; never add `package-lock.json`, `yarn.lock`, or `bun.lock`.
The pnpm version is pinned in `package.json` (`packageManager`) and in both Dockerfiles
(`PNPM_VERSION`); change them together.

## Conventions

- **Named function components**, one component per file.
- **Where components go:** Shadcn components in `components/ui/`; components shared across pages
  in `components/general/`; components used by one page in `components/page-specific/<page>/`.
  Static files (logo, favicons) live in `apps/web/public/`.
- **Never use `useEffect` for data fetching.** Use TanStack Query (`useQuery` for GET and for chart
  PNGs, `useMutation` for every POST that changes something or downloads a file), wrapped in a hook
  in `hooks/`.
- **Zod** validates every API response (`apiResponseSchema(...)` around the data schema) and the env.
- **Separate responsibilities** into hooks, services, utils, interfaces, constants, and focused
  components. Types live in `interfaces/`, not in component files.
- **Constants** live in `src/constants/`, one `*.constants.ts` per area. They hold only UI text and
  numbers the API does not provide: defaults, labels, limits and linguistic terms come from
  `GET /scales` (`useScales`), never from constants.
- **No DEMATEL maths in the browser.** Every computed value (matrices, scores, groups, thresholds,
  summary numbers, weight corrections, charts) comes from the API; the browser only formats them
  (rounding, tuple strings) and counts edited cells for the Review step.
- **300-line limit:** every code file (`.ts`, `.tsx`, `.js`, `.mjs`, `.css`), tests included, stays at
  or below 300 lines. `routeTree.gen.ts`, lockfiles, `.md`, and `.json` are exempt.
- **Debug logs:** keep temporary `console.log` calls commented out with a comment stating their
  purpose; never commit them active.
- Nothing in `apps/web` imports from, reads, or links to `qt-app/`.

## Architecture

**Layout:** `__root.tsx` renders every page inside `AppLayout`: `AppHeader` (logo, "DEMATELab",
"Cause and Effect Analysis"; no navigation), a `<main>`, and `AppFooter`, centred and at most
`max-w-layout` (1200px). Every page must work from 320px wide; wide content (matrix grid, result
tables, charts, tab list) scrolls inside its box, never the page.

**Flow:** `/` is one question per step. `FlowShell` loads `/scales`, reads `step` from the search
params, and redirects any step whose earlier steps are not answered to the first unanswered one
(`utils/flow.utils.ts`). Steps: solver, threshold, experts, factors, factor-names, expert-weights,
`matrix-1…k`, review, then results (full width). `StepFrame` handles Enter (continue; ignored in
selects, buttons and links) and Shift+Enter (back), focuses the first field, and animates in (off
under `prefers-reduced-motion`). Each step validates on OK with Qt's messages inline.

**Changing earlier answers** keeps later answers wherever valid (store actions): same-family solver
or threshold change keeps matrices; a cross-family solver change asks (`SolverChangeDialog`, Qt's
text) and resets the matrices; factor and expert counts resize keeping names and cells, asking first
when edited cells would be dropped (`ResetConfirmDialog`); a new expert count resets the weights to
`POST /weights/defaults` with a note. After a run, any change shows `OutdatedResultsBanner` with
Re-run; the old results stay until then.

**State rule (store):** `store/analysis.store.ts` holds the answers and, after a run, the
**request snapshot** with its results. Results, charts, exports and the AI explanation always use the
snapshot, never the current answers, so edits after a run never mix with old results. Nothing is
persisted (no localStorage). `MatrixCell` subscribes to its own cell, and `setCell` copies only the
changed row, so editing a cell does not re-render the grid.

**Matrix editor:** native `<select>` per cell, rows and columns virtualised with
`@tanstack/react-virtual` (fixed sizes in `MATRIX_GRID`), header row and column sticky. Only the open
expert's step is mounted. Tests call `stubLayout()` (`test/render.tsx`) because jsdom has no layout.

**Results:** charts are PNGs from the API (`dpi=100` on screen, `300` for downloads), shown through
object URLs (`useObjectUrl`) with 1.2× zoom steps. The summary PNG is captured in the browser with
`html-to-image` from an off-screen copy of `SummaryPanel`. Downloads use `saveBlob`.

**AI explanation:** the AI Provider and Model selects come from `GET /explanations/providers`
(`useExplanationProviders`); a provider change resets the model to its default. Azure OpenAI is a
free-text deployment name with no default, and Generate stays disabled until it is filled. Failures show
in a toast (`toast.error` from `sonner`; one themed `<Toaster />` in `__root.tsx`); the status line shows
progress.

**API key rule:** the AI provider key lives only in `ExplanationPanel`'s component state (a password
input). It is sent once in the request body and never put in the store, query keys, mutation
variables (`useExplanation` passes it through a ref), URLs or logs. Tests assert this.

**API integration:** requests go to `${env.VITE_API_BASE_URL}/api/v1/*` through `apiData()` (JSON)
or `apiBlob()` (files) in `utils/api.utils.ts`; non-OK responses throw `ApiError` with the API's
public message (for 422 validation errors, the first field's message). Endpoint paths live in
`constants/api.constants.ts`. The API is public: no cookies, no auth.

**TypeScript and styling:** strict mode; `@/*` → `./src/*`, always used for internal imports.
Tailwind v4 with CSS config in `styles.css`; `cn()` from `@/lib/utils`. Shadcn on **Base UI**
(`base-nova`), never Radix: compose with the `render` prop, not `asChild`; switch generated
`from "cn"` imports to `@/lib/utils`. Domain colours `cause`, `effect`, `cell-edited` are theme
tokens (the cause/effect hues are darkened in lightness only, for WCAG AA badge text).

**File naming:** components in PascalCase; `*.utils.ts`, `*.service.ts`, `*.hook.ts`,
`*.interface.ts`, `*.constants.ts`, `*.store.ts`; tests co-located as `<name>.test.ts(x)`.

## Environment

`apps/web/.env` (template `.env.example`), validated in `src/env.ts`. `VITE_*` values are inlined into
the browser bundle: never put secrets in it. Production: `VITE_APP_ENV=production` and an empty
`VITE_API_BASE_URL`.

## Testing

Vitest with `@testing-library/react` and `jsdom` (`vitest.config.ts`). Mock `fetch` with
`vi.stubGlobal` in service tests and services with `vi.mock` in component tests; use the API-shaped
fixtures in `src/test/fixtures.ts` and `renderWithQuery` from `src/test/render.tsx`. `FlowShell`
tests mock `@tanstack/react-router` (`useSearch`, `useNavigate`, `Navigate`).

## Pitfalls

❌ `useEffect` for data fetching → ✅ TanStack Query hooks  
❌ Hard-coded scales, labels or limits → ✅ `useScales()`  
❌ Computing DEMATEL values in the browser → ✅ The API  
❌ The API key in the store, a query key, mutation variables or a log → ✅ Component state only  
❌ Results built from current answers → ✅ The store's snapshot  
❌ Radix primitives or `asChild` → ✅ Base UI and the `render` prop  
❌ Hardcoded API URLs or raw `import.meta.env` → ✅ `env` from `@/env` and the API utils  
❌ Unvalidated API responses → ✅ Zod  
❌ Editing `routeTree.gen.ts` → ✅ Let the router plugin regenerate it  
❌ A code file over 300 lines → ✅ Split it by responsibility
